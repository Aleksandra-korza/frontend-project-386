# Requirements Analysis

## Цель

Преобразовать исходное техническое задание в структурированный документ требований.

## Правила

- Используй предоставленное техническое задание как основной источник.
- Не придумывай требования, которых нет в источнике.
- Разделяй подтверждённые требования и предположения.
- Не выбирай технологический стек самостоятельно.
- Не переходи к реализации.
- Не изменяй исходный код.
- Если информации недостаточно, формулируй открытый вопрос.

## Порядок работы

1. Изучи исходное техническое задание.
2. Определи цель и границы приложения.
3. Выдели роли пользователей.
4. Опиши сценарии владельца и гостя.
5. Составь список функциональных требований.
6. Выдели нефункциональные требования.
7. Зафиксируй бизнес-правила и ограничения.
8. Выдели требования к API и генерации SDK.
9. Зафиксируй требования к Docker.
10. Составь список решений, которые ещё нужно принять.

## Формат результата

1. Описание приложения.
2. Роли пользователей.
3. Пользовательские сценарии.
4. Функциональные требования.
5. Бизнес-правила.
6. Нефункциональные требования.
7. Технические ограничения.
8. Критерии приёмки.
9. Открытые вопросы.

Для каждого требования используй уникальный идентификатор, например FR-01 или NFR-01.
