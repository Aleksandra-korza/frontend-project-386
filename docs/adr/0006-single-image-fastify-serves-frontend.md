# Один Docker-образ: Fastify раздаёт собранный frontend

Приложение собирается в **один** Docker-образ, в котором Fastify обслуживает и API (`/api/*`), и собранный frontend (`apps/frontend/dist`) через `@fastify/static`. Клиентские адреса (`/book`, `/admin` и т. д.) получают `index.html` (fallback для React Router, ADR-0001), а `/api/*` без маршрута — JSON `404`. Frontend обращается к API по относительным адресам SDK, поэтому одного origin достаточно: CORS, прокси и переменные окружения адреса API не нужны. Деплой — один бесплатный Render Web Service (`runtime: docker`).

Решение принято при согласовании плана шага 7 (родительская задача #26), закрывает OQ-07 и OQ-08.

## Considered Options

- **Отдельные сервисы** (Render Static Site для frontend + Web Service для API) — два деплоя и два origin: нужны CORS или переписывание путей, адрес API при сборке frontend; больше точек отказа ради статики из нескольких файлов.
- **Nginx перед Node в одном образе** — второй процесс и конфигурация без выигрыша при текущей нагрузке.

## Consequences

- Backend получает зависимость `@fastify/static` и параметр `buildApp({ staticDir })`; в тестах и dev-режиме (Vite) статика выключена.
- Образ содержит только prod-зависимости backend и собранные файлы; сборка frontend и TypeScript — на промежуточном этапе.
- Один процесс — одно in-memory хранилище (D-06), поэтому атомарность бронирования по ADR-0003 сохраняется; при переходе на несколько экземпляров или постоянное хранилище решение пересматривается вместе с ADR-0003.
