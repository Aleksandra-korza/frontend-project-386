# Клиентская маршрутизация — React Router в data mode

Frontend становится многостраничным: главная страница, страница записи (`/book`), страница «не найдено», а на следующих этапах — шаги записи и раздел владельца `/admin`. Мы используем React Router в режиме data mode (`createBrowserRouter` + `RouterProvider`): это стандартный роутер для React + Vite, а встроенные страница ошибок и загрузчики данных (`loader`) понадобятся каталогу типов встреч, который будет получать данные через сгенерированный SDK.

## Considered Options

- **Самописный переключатель по `location.pathname`** — без зависимостей, но вложенные маршруты, параметры, подсветку активного пункта и загрузку данных пришлось бы писать вручную и вскоре переписывать.
- **TanStack Router** — типобезопасный, но сложнее в настройке и добавляет генерацию маршрутов поверх уже существующей генерации SDK.
- **React Router в framework mode** — требует собственного плагина Vite и меняет сборку (SSR); для SPA это лишнее.
- **React Router в declarative mode** (`<BrowserRouter>`) — проще, но без загрузчиков данных; переход на data mode позже потребовал бы переписать описание маршрутов.

## Consequences

- В продакшене сервер должен отдавать `index.html` для клиентских адресов (например, при обновлении страницы на `/book`). Решение отложено до этапа Docker (см. `docs/open-questions.md`).
- Тесты страниц используют тот же список маршрутов через `createMemoryRouter`.
