# Спецификация: Docker-образ и деплой на Render

> Статус: согласовано 2026-11-20. Родительская задача [#26 «Docker и деплой»](https://github.com/Aleksandra-korza/frontend-project-386/issues/26), подзадачи #27–#31.
> Требования: TC-09, TC-10, NFR-04, AC-29 (`docs/requirements.md`). Решение об образе — ADR-0006. Сервис записи — `docs/specs/booking.md`.

## 1. Исходное состояние

| Что                  | Сейчас                                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сборка               | `pnpm build`: backend — `tsc` → `apps/backend/dist` (`node dist/server.js`); frontend — `tsc -b && vite build` → `apps/frontend/dist`               |
| Обращение к API      | SDK по относительным адресам `/api/...`; в dev Vite проксирует `/api` на `127.0.0.1:4000` — в production frontend и API на одном origin             |
| Раздача frontend     | отсутствует: Fastify отвечает только на `/api/*`                                                                                                    |
| Переменные окружения | `PORT` (по умолчанию `4000`), `HOST` (по умолчанию `127.0.0.1`); секретов нет                                                                       |
| Контракт в runtime   | `apps/backend/dist/contract.js` читает `../../../api/generated/openapi.json` — в образе сохраняется раскладка `apps/backend/dist` + `api/generated` |
| Хранение данных      | память одного процесса (D-06); атомарность бронирования держится на этом (ADR-0003)                                                                 |

## 2. Раздача frontend из Fastify (#27)

- `buildApp({ staticDir })`: если каталог задан, регистрируется `@fastify/static` с корнем `staticDir`; без него (тесты, dev через Vite) раздачи нет.
- `GET`/`HEAD` вне `/api`: существующий файл отдаётся как есть; иначе запрос, ожидающий HTML, получает `index.html` (fallback клиентских адресов: `/book`, `/book/:typeId`, `/book/:typeId/confirm`, `/admin`).
- `/api/*` без маршрута — JSON `404` с единым телом ошибки, никогда не `index.html`.
- `server.ts` передаёт каталог `apps/frontend/dist` (относительно собранного backend; переопределяется `STATIC_DIR`), если он существует.

## 3. Docker-образ (#28)

Многоэтапный `Dockerfile` в корне:

| Этап    | Содержимое                                                                                                                                                                                                                                                                                   |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| deps    | `node:24-slim`, corepack → pnpm из `packageManager`; манифесты и `pnpm-lock.yaml` → `pnpm install --frozen-lockfile` (dev-зависимости нужны для сборки)                                                                                                                                      |
| build   | исходники `api/`, `apps/` → `pnpm build`; codegen не выполняется — `api/generated`, SDK и типы backend хранятся в Git                                                                                                                                                                        |
| runtime | `node:24-slim` без pnpm, mise, TypeSpec, Playwright; только prod-зависимости backend, `apps/backend/dist`, `api/generated/openapi.json`, `apps/frontend/dist`; `NODE_ENV=production`, `HOST=0.0.0.0`, `PORT` по умолчанию `4000`; `USER node`; `CMD ["node", "apps/backend/dist/server.js"]` |

- `.dockerignore` — белый список (`*`, затем `!` нужных путей): в контекст не попадают `.git`, `node_modules`, `.env*`, `.claude/`, личные и прочие неотслеживаемые файлы.
- Локальная проверка: `docker build`, контейнер с `PORT` по умолчанию и `PORT=10000`; `/api/health` → JSON, `/` и `/book` → HTML. Порт `3000` на машине разработчика занят посторонним контейнером — не использовать.
- В образе нет `.git`, `.env*`, dev-зависимостей (vite, typescript, vitest, playwright) и исходников тестов.

## 4. CI (#29)

Job `docker` в `.github/workflows/check.yml`: сборка образа, запуск контейнера с `PORT=10000`, ожидание готовности, проверки `/api/health`, `/`, `/book`; при падении — логи контейнера. Actions — по полному SHA. `hexlet-check.yml` не меняется.

## 5. Render (#30, #31)

`render.yaml` (Blueprint):

| Поле                | Значение      | Зачем                               |
| ------------------- | ------------- | ----------------------------------- |
| `type`              | `web`         | публичный web service               |
| `runtime`           | `docker`      | сборка из `Dockerfile` в корне      |
| `plan`              | `free`        | только бесплатный тариф             |
| `healthCheckPath`   | `/api/health` | вместо проверки открытого TCP-порта |
| `branch`            | `main`        | деплой из основной ветки            |
| `autoDeployTrigger` | `checksPass`  | деплой только после зелёного CI     |

- Render задаёт `PORT` (по умолчанию `10000`); образ слушает `0.0.0.0`.
- Сервис создаётся **в Dashboard по Blueprint**. Render MCP (`create_web_service`) не поддерживает тариф `free` — через MCP сервис не создаётся.
- **Render MCP** подключается к Claude Code OAuth-плагином: `/plugin install render@claude-plugins-official`, `/reload-plugins`, вход в браузере. `.mcp.json` в репозитории нет, ключи и токены в Git не хранятся. MCP используется для выбора workspace, просмотра сервиса, деплоев, логов и метрик; операции, меняющие сервис, согласуются с владельцем.
- **Railway** — запасной вариант: тот же образ (Railway передаёт `PORT`), health check `/api/health`.

## 7. Проверка опубликованного приложения (#31)

1. `/api/health` → `{"status":"ok"}`; `/book` открывается напрямую и после обновления страницы.
2. Владелец создаёт в `/admin` тип встречи (например, `deploy-check-30`, 30 мин); тип виден в каталоге `/book`.
3. Гость бронирует слот → «Бронирование подтверждено. До встречи!»; бронирование видно в `/admin`.
4. Повторное бронирование того же слота → `409 SLOT_TAKEN`; бронирование другого типа (60 мин), пересекающее занятое время, → `409`; примыкающий слот бронируется.
5. Перезапуск (Restart / Manual Deploy) или сон: типы встреч и бронирования пропадают, сервис снова отвечает на `/api/health`.

## 8. Ограничения и риски

| Ограничение                                                                                                     | Последствие и решение                                                                 |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Free засыпает после 15 минут без входящих запросов; пробуждение около минуты                                    | первый запрос медленный — описано в README                                            |
| Данные в памяти процесса; теряются при деплое, перезапуске, сне; Render может перезапустить Free в любой момент | осознанное решение D-06; постоянное хранилище — отдельный этап с пересмотром ADR-0003 |
| 750 бесплатных часов в месяц на workspace                                                                       | одного сервиса достаточно                                                             |
| Один экземпляр                                                                                                  | атомарность ADR-0003 сохраняется; масштабирование не включается                       |
| Во время деплоя ненадолго работают старый и новый экземпляры                                                    | данные расходятся, но и так теряются при деплое                                       |
| Нет SSH и постоянных дисков на Free                                                                             | диагностика — логи через Dashboard или MCP                                            |
